# 污染物排放控制标准审核

## 1. Skill结构

本Skill覆盖21题中的13道排放标准题，不拆成4个独立大Skill：

```text
07 污染物排放控制标准审核
├─ A 废水路径与标准节点
├─ B 大气污染源—标准覆盖
├─ C 噪声厂界适用性
└─ D 固体废物管理文件与处置闭环
```

标准知识检索由支持模块`retrieve-eia-discharge-standard-knowledge`提供，不作为独立审核结论。

## 2. 输入

```json
{
  "question_id": "",
  "question": "",
  "medium": "wastewater | air | noise | solid_waste",
  "report_context": "",
  "reference_bundle": []
}
```

`reference_bundle`为空时，仍执行报告内部审核。

## 3. 统一双层结论

### 第一层：报告内部审核

检查：

- 产污工序是否完整；
- 污染物是否完整；
- 排放形式和去向是否明确；
- 正文、标准表、影响分析、监测计划和监督检查清单是否一致；
- 数值、单位、表号和标准名称在报告内部是否一致；
- 是否存在未被任何标准覆盖的污染源。

### 第二层：外部规范审核

有正式资料包时检查：

- 标准版本和实施状态；
- 地区、行业、工艺、污染物和排放形式；
- 标准表号、级别、限值、单位和附加条件；
- 国家与地方标准衔接；
- 报告编制时点适用性。

## 4. A：废水子流程

建立：

```text
废水类型
→ 处理方式
→ 是否回用
→ 回用用途
→ 企业排放口
→ 是否纳管
→ 污水处理厂
→ 尾水受纳水体
→ 各节点引用标准
```

内部审核重点：

- 报告不同章节对直排、间排、纳管和委外是否一致；
- 企业排口、污水处理厂尾水和回用水标准是否在报告中被混用；
- 污水处理厂名称、河道和排放口信息是否一致；
- 废水量和污染物是否前后一致。

无外部标准时，可判报告内部路径是否清楚，但外部适用性标记`not_performed`。

## 5. B：废气子流程

建立：

```text
产气工序
→ 污染物
→ 收集形式
→ 治理设施
→ 排气筒
→ 有组织标准
→ 厂界无组织标准
→ 厂区内无组织标准
```

内部审核重点：

- 所有产气工序是否进入标准表；
- 有组织、厂界和厂区内是否混淆；
- 同一排气筒在不同章节采用的标准和限值是否一致；
- 达标分析、监测计划和监督检查清单是否一致；
- 是否遗漏恶臭、燃烧废气或特征污染物。

## 6. C：噪声子流程

建立：

```text
项目位置
→ 报告填报声功能区
→ 各侧厂界
→ 昼间/夜间生产
→ 标准类别
→ 限值
→ 预测和监测计划
```

内部审核重点：

- 报告是否说明夜间生产；
- 预测仅评价昼间时，监测计划为何列夜间；
- 各侧厂界是否统一执行同一类别；
- 预测值、标准值和达标结论是否一致。

外部区划和类别真实性需要正式区划资料。

## 7. D：固体废物子流程

建立：

```text
废物名称
→ 产生工序
→ 报告填报类别/代码
→ 数量
→ 贮存设施
→ 贮存周期
→ 利用或处置去向
→ 各章节引用文件
```

内部审核重点：

- 产污环节、固废正文、汇总表、附表和监督检查清单是否完整；
- 分项数量与小计是否一致；
- 同一废物在不同表格中的名称、代码和数量是否一致；
- 报告所称一般固废是否进入一般固废路径；
- 报告所称危废是否进入危废暂存和资质单位处置路径；
- 暂存能力和周期是否与报告列示数量自洽。

危险废物属性、代码和标准版本的正式正确性必须使用外部资料包核验。

## 8. 结论规则

### 有正式参考资料

输出：

- `正确`
- `存在问题`
- `待人工复核`

### 无正式参考资料

仍必须输出内部审核结果。最终输出可以是：

- `部分完成：报告内部一致，外部适用性未核验`
- `存在问题：报告内部已经发现矛盾`
- `待人工复核：报告自身关键证据缺失`

禁止把所有无资料情况统一写成“无法判断”。

## 9. 禁止事项

- 不使用模型参数记忆补充限值；
- 不把报告自己引用的标准视为已经被外部验证；
- 不因为标准编号相似就认定适用；
- 不读取Word批注和人工修改意见；
- 不硬编码任何测试项目答案。
