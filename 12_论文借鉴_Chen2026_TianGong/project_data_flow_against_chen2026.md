# 本项目数据流与 Chen 2026 对比分析

> 生成日期：2026-07-03  
> 目的：基于当前仓库材料，判断哪些数据与 Chen 2026 技术路线相似且有用，哪些只能作为候选材料，哪些不适合进入论文主数据流。  
> 研究边界：本课题不做模型微调，不做自动审批；核心是“佛山市塑胶行业环评审核场景下的标准依据库、审核技能库、样本链证据库、大模型辅助和人工/专家复核”。

## 1. 总体结论

本项目与 Chen 2026 最相似、也最值得借鉴的部分，不是 fine-tuning，而是以下 5 个方法环节：

1. **权威材料结构化**：Chen 使用环境教材和补充材料；本项目对应佛山塑胶指南、标准规范、Dify 知识库和地方审核材料。
2. **文档切块与混合检索**：Chen 使用向量库和全文库；本项目已有 `build_hybrid_index.py`、`hybrid_retrieve.py`、`eia_plastic_hybrid.sqlite` 和 `corpus_chunk.schema.json`。
3. **种子问题驱动任务构建**：Chen 用种子问题召回材料并生成 QA；本项目当前主 QA 工作簿已形成 1037 行候选任务，并补充 95 条样本链 QA，已筛选 60 道正式评价候选题，但整体仍只能作为候选审核任务池。
4. **工作流化任务执行**：Chen 比较 agentic workflow；本项目最强对应是 15 个审核 skill + 1 个总审核 skill。
5. **人工/专家验证与评价**：Chen 有 expert-in-the-loop；本项目已有 schema 和人工复核字段，但真实专家复核、金标答案和完整样本链仍不足。

因此，当前数据流应以 **标准依据库 + 审核技能库** 为主干，以 **样本链和 QA** 为候选评价材料，以 **Chen 2026** 为方法参照，而不是把全部现有材料都当成可直接实验的数据集。

## 2. Chen 2026 的数据流骨架

Chen 2026 的可借鉴数据流可以简化为：

```text
权威环境语料
  -> 文档解析与切块
  -> 向量检索 + 全文检索
  -> 种子问题驱动召回
  -> 结构化 QA / 任务生成
  -> 专家验证与剔除
  -> 模型 / 工作流 / 策略评价
  -> 错误分析与统计检验
```

迁移到本课题时，应改写为：

```text
佛山塑胶指南 / 标准规范 / Dify 知识库 / 报告样本 / 修改意见
  -> 标准卡、技能步骤、报告片段、修改意见片段
  -> 混合检索：语义召回 + 标准号/污染物/工艺关键词召回
  -> 审核任务与候选修改意见生成
  -> 人工复核与金标答案校准
  -> A/B/C/D 知识条件对照实验
  -> 错误案例分析与技能库迭代
```

## 4. 哪些数据最像 Chen，且对本课题最有用

### 4.1 标准依据库：最像 Chen 的“权威语料结构化”

**对应 Chen：** 权威环境教材 / 补充材料 -> 结构化 chunk。

**本项目对应：**

- `03_指南解析_明文标准库/standard_cards.jsonl`
- `03_指南解析_明文标准库/standard_cards.json`
- `03_指南解析_明文标准库/cards_by_skill/`
- `03_指南解析_明文标准库/skills_to_standard_mapping.yaml`
- `03_指南解析_明文标准库/Dify工作流知识库/`
- `03_指南解析_明文标准库/quality/QUALITY_CHECK.md`

**有用原因：**

- 标准依据库回答“依据是什么”，是避免大模型泛泛而谈的基础。
- `standard_cards.jsonl` 已经具备结构化字段，包括 skill、来源文件、证据字段、阈值、公式、检查逻辑和人工复核边界。
- `cards_by_skill/` 能直接支持“审核任务 -> 调用相关标准卡”的数据流。

**当前风险：**

- 37 条主标准卡数量不算多，覆盖面仍需扩展。
- 292 条 Dify 解析候选条目不能直接当权威依据，需要人工校准。
- `QUALITY_CHECK.md` 已标出 GB3096 夜间限值、环保投资 5% 经验阈值、活性炭参数缺少独立卡等风险。

**数据流定位：**

```text
进入主数据流，但必须带 review_status。
建议字段：active / needs_review / deprecated / candidate。
```

## 5. 哪些数据有用，但只能作为候选层

### 5.1 QA 候选题与样本链 QA

**文件：** `05_QA测试集/seed_qa_942题_151项目_phase1+phase2合并_sample_chain_95_20260706.xlsx`

**当前状态：**

- 工作表 `seed_qa` 共 1037 行、20 列，包含原始候选 QA 和样本链增强 QA。
- 另有 95 条样本链 QA，可作为金标候选来源。
- 当前已筛选 60 道正式评价候选题。
- 已有字段包括 `date`、`canonical_project_id`、`question_id`、`audit_module`、`question`、`answer`、`evidence`、`source_basis`、`scarcity_check`、`verifiability_check`、`manual_check` 等。
- 但 `manual_check` 后的部分人工审核列名和内容存在编码污染，例如列名显示为乱码。

**有用原因：**

- 它类似 Chen 的 seed question / generated QA 数据池。
- 可用于召回标准依据、发现审核任务类型、构建候选评价题。

**不能直接用的原因：**

- QA 是候选题，不是金标。
- 有些答案可能由模型生成或自动整理，必须检查证据是否真实支撑。
- 编码污染会影响字段读取、人工复核和后续统计。

**建议处理：**

```text
1037 行候选 QA + 95 条样本链 QA
  -> 修复字段名和编码
  -> 按 evidence/source_basis/manual_check 筛选
  -> 剔除证据不足、来源不匹配、行业边界不清题目
  -> 先形成 60 道正式评价候选题，再人工复核为 40-60 道 verified gold
```

### 5.2 Dify 解析候选标准条目

**文件：** `03_指南解析_明文标准库/dify_kb_standard_entries_pilot.jsonl`

**当前状态：** 292 条。

**有用原因：**

- 可作为标准库扩展来源。
- 有助于补充当前 37 条主标准卡覆盖不足的问题。

**不能直接用的原因：**

- 自动解析条目可能重复、过细、过泛或来源不清。
- 标准限值、表号、适用条件、版本有效性必须人工校准。

**建议处理：**

```text
292 条候选条目
  -> 去重
  -> 归并到 15 个 skill
  -> 标注 hard_law / guidance / experience
  -> 人工校准后再进入 standard_cards.jsonl
```

### 5.3 样本链材料

**目录：** `05_样本链（按项目组织）/`

**当前状态：**

- 33 个项目目录，含 `EXCLUDED_*`、`NEW_PL*`、`REVIEW_*`、`SH_*` 等分组。
- `_元数据/sample_chain_explanation.md` 说明：理想 A 类完整链为“受理公告 -> 修改意见 -> 终稿 -> 批复”，但当前数据集中无 A 类样本。
- `_元数据/plastic_project_sample_chain_matching_v1_v0620.csv` 有 120 行匹配记录，包含是否适用塑胶指南、是否涉胶水/复合、是否有受理公告、修改意见、终稿、批复等字段。

**有用原因：**

- 样本链最能体现你的课题不是普通问答，而是真实审核场景。
- 修改意见和技术审查意见可以作为真实错误标签。
- 终稿和批复可用于校准修改是否被采纳。

**不能直接用的原因：**

- 当前 A 类完整链不足。
- 很多项目只有批复或数据库链条标记，缺报告全文、修改意见、终稿等中间环节。
- 只凭批复文件难以校准“模型应发现什么问题”。

**建议处理：**

```text
样本链材料
  -> 按 A_complete / B_partial / C_single 重新分级
  -> 优先补 3-5 个涉胶水、复合、熟化、VOCs 治理典型项目完整链
  -> 每条修改意见拆成：问题类型 + 报告证据 + 标准依据 + 修正结果
```

### 7.3 只有批复、没有报告和修改意见的单点样本

**原因：**

- 批复能提供管理要求，但不能还原报告原文问题。
- 缺少受理报告和修改意见时，无法判断模型是否发现了真实审核问题。

**建议：**

```text
可用于 approval_alignment 或 case_experience_candidate。
不进入 gold evaluation。
```

### 7.4 编码污染或字段不稳定的 QA 列

**原因：**

- 当前 QA Excel 中部分人工审核列名和内容存在乱码。
- 这些字段若直接进入统计，会造成字段错读和结论不可信。

**建议：**

```text
先修复字段名，再决定是否保留字段内容。
建议保留原始文件，另建 cleaned 版本。
```

## 8. 推荐的数据分层

## 10. 数据是否有用的判定标准

后续清理数据时，可以按以下标准判断：

| 判断问题 | 是 | 否 |
| --- | --- | --- |
| 是否属于佛山塑胶指南适用范围？ | 可进入候选 | 降为参照或排除 |
| 是否涉胶水、涂胶、复合、熟化、VOCs 治理等核心场景？ | 优先进入样本链 | 仅作辅助参照 |
| 是否能追溯到标准条款、报告片段、修改意见或批复？ | 可进入任务候选 | 暂不进正式评价 |
| 是否已人工复核字段、来源和结论？ | 可进入正式评价 | 只能作为候选 |
| 是否只是论文方法说明或中期汇报材料？ | 只进方法参考层 | 不进审核 RAG 语料 |
| 是否只有批复而没有报告或修改意见？ | 可作案例背景 | 不作金标问题 |
| 是否存在乱码、重复、来源不清？ | 先清洗 | 不直接使用 |

## 11. 近期最该整理的数据

### 11.1 第一优先级：QA 清洗与正式题筛选

目标：从 60 道正式评价候选题中优先复核 10-15 道样例，并逐步扩展到 40-60 道 verified gold。

具体任务：

1. 修复人工审核列乱码。
2. 统一字段名：`manual_check`、`human_decision`、`human_note`、`evidence_status`、`candidate_status`。
3. 按证据完整度分级：high / medium / low。
4. 剔除证据不足、问题来源不匹配、行业边界不清的题。
5. 每题绑定一个主 skill 和一个或多个标准卡。

### 11.2 第二优先级：标准库合并与校准

目标：把标准库从“候选多版本”整理为“可调用主库 + 候选补充库”。

具体任务：

1. 以 `standard_cards.jsonl` 为主库。
2. 从 v3 的 71 条和 Dify 292 条候选中补充缺口。
3. 去重并增加字段：`review_status`、`authority_level`、`applicability_boundary`、`hard_law`。
4. 优先校准 GB 31572、GB 37822、DB44/2367、三线一单、产污系数、活性炭参数。

### 11.3 第三优先级：样本链补强

目标：补出能支撑论文案例分析和小规模实验的真实链条。

具体任务：

1. 从 120 行样本链匹配表中筛选 `is_plastic_guide_applicable=Y` 且 `is_glue_or_composite=Y` 的项目。
2. 优先查找是否有受理报告、修改意见、终稿、批复。
3. 至少补 3-5 个接近 A 类完整链的项目。
4. 将修改意见拆为结构化标签：审核模块、报告证据、标准依据、修正结果。

### 11.4 第四优先级：检索索引正式化

目标：让混合检索真正服务审核，而不是只服务方法演示。

具体任务：

1. 更新 `eia_plastic_hybrid_index.yaml`，加入样本链目录。
2. 将 `evidence_type` 明确分为 standard、audit_skill、sample_report、review_comment、approval、qa_task。
3. 抽样 20 个查询测试召回质量。
4. 记录召回失败案例，反向修正 chunk 和 metadata。
