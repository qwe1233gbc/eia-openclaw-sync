# 环境质量现状数据审核

## 1. 核心改动

本Skill不再因为官方公报缺失而整题拒答，而是固定输出两层结果：

1. `report_internal_result`：报告内部核验；
2. `external_validation_result`：官方公报核验。

## 2. 输入

```json
{
  "question_id": "",
  "question": "",
  "report_context": "",
  "reference_bundle": []
}
```

`reference_bundle`可以为空。为空时仍必须完成报告内部审核。

## 3. 报告内部审核

### 大气

核对：

- 报告所称公报名称和年份；
- 正文分析年份；
- 表格标题与列年份；
- 污染物数值、单位、变化率和达标状态；
- “上升/下降”与计算符号是否一致；
- 达标区结论与报告自身数据是否一致。

### 地表水

核对：

- 项目排水去向；
- 河涌、河流、断面名称；
- 公报名称和年份；
- 表格标题、断面和水质类别；
- 报告结论是否与表格一致；
- 是否出现对象错配、列错位或OCR风险。

内部可复算内容直接计算，不需要外部知识。

## 4. 官方公报核验

只有`reference_bundle`包含经确认的正式公报时，核验：

- 公报名称、年份和发布单位；
- 报告数值与公报原文；
- 水体、断面和统计口径；
- 报告编制时点可获得的近三年数据；
- 是否存在更新版本。

## 5. 不同资料状态下的输出

### 有正式公报

可输出完整的“正确/存在问题”。

### 无正式公报

不得只写“无法判断”。应输出：

- 报告内部是否一致；
- 已完成的算术和对象核对；
- `external_validation_result.status=not_performed`；
- 最终判定为`部分完成`；
- 明确列出需要补充的公报名称、年份和数据项。

## 6. 问题分级

- 数据实质错误；
- 年份或对象错误；
- 表格与正文不一致；
- 变化率或正负号错误；
- 公报标题、文号或引用笔误；
- OCR/解析结构风险；
- 无内部问题但官方真实性尚未核验。
