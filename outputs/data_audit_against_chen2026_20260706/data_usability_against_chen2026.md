# 按 Chen 2026 思路梳理当前数据可用性

> 结论日期：2026-07-06  
> 研究边界：本课题不做微调，不做自动审批，重点是佛山市塑胶行业环评技术审查中的标准依据库、审核技能库、样本链证据库和大模型辅助评价。

## 1. 按 Chen 论文思路重构你的数据流

Chen 2026 的核心不是单纯堆数据，而是把环境领域任务组织成一个可执行的数据流。抽象后可理解为：

```text
专业材料
  -> 结构化知识
  -> 任务/问答构造
  -> 工作流或工具调用
  -> 人工/专家验证
  -> 评价与迭代
```

迁移到你的课题，应该改写为：

```text
地方指南 / 标准规范 / 环评报告 / 修改意见 / 批复
  -> 标准依据库 + 审核技能库 + 样本链证据库
  -> 候选QA + 样本链QA + 人工精校金标题
  -> A/B/C/D 知识条件对照
  -> 人工评分和专家复核
  -> 标准库、技能库和样本链证据迭代
```

因此，你的数据不能简单按“有多少文件、多少题”判断，而要按它在这个数据流中的位置判断是否可用。

## 2. 当前最可用的数据

### 2.1 标准依据库：可用，但要标注复核状态

**当前数据：**

- 主标准卡约 37 条；
- 旧版深度标准库约 71 条；
- Dify 候选标准条目约 292 条；
- 按审核技能对齐的标准条目约 124 条。

**按 Chen 思路的对应位置：**

对应“专业材料结构化”和“可检索知识基础”。

**可用性判断：**

可用，但分层使用。

**可以直接用于：**

- 中期汇报；
- 方法章节；
- A/B/C/D 实验中的 B 组和 D 组；
- 标准适用、排放标准、VOCs、危废、源强核算等任务的依据检索。

**不能直接用于：**

- 不宜把 Dify 292 条全部当成权威标准；
- 不宜不经校准就作为正式评分依据；
- 不宜混淆“强制标准”“地方指南”“经验规则”。

**下一步处理：**

保留主标准卡作为主库；旧版深度标准库和 Dify 条目作为候选补充库；每条增加 `review_status`、`authority_level`、`applicability_boundary`。

## 3. 当前最有研究特色的数据

### 3.1 审核技能库：可用，是你区别于普通 RAG 的核心

**当前数据：**

- 15 个单项审核技能；
- 1 个总审核技能；
- 覆盖行业分类、三线一单、建设内容、标准适用、源强核算、废气收集、活性炭、危废、VOCs 总量等。

**按 Chen 思路的对应位置：**

对应“工作流化任务执行”和“工具/技能调用”。

**可用性判断：**

高度可用，建议作为论文主线之一。

**可以直接用于：**

- 论文方法章节；
- C 组和 D 组对照实验；
- 解释本课题不是普通问答，而是把审核经验拆解为技能；
- 连接标准库和样本链 QA。

**不能直接用于：**

- 不能把技能库说成已经验证有效；
- 不能替代标准依据；
- 不能替代专家判断。

**下一步处理：**

每个技能绑定三类东西：

```text
对应标准依据
对应样本链专家意见
对应QA任务
```

这样技能库才不是“写出来的流程”，而是有证据支撑的审核方法。

## 4. 当前最关键的证据数据

### 4.1 样本链数据：可用，是正式评价集的来源

**当前数据：**

- 近三年 C292 候选样本链 49 个；
- 本地下载代表性样本链 10 个；
- 四类主链文件：受理公告/公示版、报批稿/终稿、修改意见/技术评估意见、批复。

**按 Chen 思路的对应位置：**

对应“真实语料”和“专家验证/外部证据”。

**可用性判断：**

非常可用，但要分级。

**可以直接用于：**

- 中期汇报；
- 样本链证据库构建；
- 专家意见转 QA；
- 典型案例分析；
- 正式评价集候选来源。

**不能直接用于：**

- 不能说 49 个都是金标样本；
- 不能说 10 个本地样本链都已经人工精校；
- 不能只凭批复判断模型应该发现什么问题。

**下一步处理：**

把样本链分成三类：

| 类型 | 含义 | 用途 |
|---|---|---|
| A 类完整链 | 四类文件齐全，且有明确专家意见/技术评估意见 | 优先做金标题 |
| B 类半链 | 有部分主链文件，但缺关键修改意见或终稿 | 用于案例背景或补充 |
| C 类单点材料 | 只有批复、公告或单个报告 | 不进入正式评价集 |

```text

usage_role = coverage_pool / evaluation_candidate / formal_eval
evidence_chain_level = no_chain / expert_comment / report_page / standard_clause / closed_loop
```

## 6. 当前最适合做正式评价集候选的数据

### 6.1 样本链 QA 95 条：可用，是金标候选核心

**按 Chen 思路的对应位置：**

**可用性判断：**

**可以直接用于：**

- 金标候选集；
- 样本链证据库案例；
- 后续 A/B/C/D 实验题源。

- 不能全部不经人工检查就做正式评分；

**下一步处理：**

```text

批复是否体现
人工参考答案
评分维度
```

筛完后，这 40-60 条才可以作为正式评价集。

## 8. 当前暂时不可用或不建议直接使用的数据

### 8.1 未校准的 Dify 候选条目

问题：

- 可能重复；
- 可能来源不清；
- 可能把经验规则写成标准；
- 可能缺少适用边界。

处理：

只作为候选补充，不直接进正式标准主库。

### 8.2 只有批复、没有修改意见或报告正文的单点样本

问题：

- 批复能说明最终管理要求；
- 但不能还原报告原始问题；
- 也不能判断模型是否应发现该问题。

处理：

可作为案例背景，不进入正式评价集。

### 8.3 工作流自动生成但无证据绑定的 QA

问题：

- 题目可能合理，但答案未必有真实证据；
- 不能用来评价模型准确率。

处理：

保留在候选池，等待人工复核。

### 8.4 旧版本、重复版本、未说明来源的文件

问题：

- 容易让后续人工检查混乱；
- 容易污染知识库；
- 不利于论文表述。

处理：

标记为 deprecated 或 archive，不进入主数据流。

## 11. 你现在应该怎么处理数据

优先级如下：

1. **不要继续扩 942 这类候选题数量**  
   当前数量已经够，继续扩意义不大。

2. **从 95 条样本链 QA 中筛 40-60 条正式题**  
   这是最关键的下一步。

3. **给正式题补齐证据链**  
   每题至少要有报告证据、标准依据、专家意见或技术评估意见。

4. **把标准库分成主库和候选库**  
   主库用于实验，候选库用于后续补充。

5. **把技能库绑定到真实题目**  
   每个正式题都标注对应哪个审核技能。

6. **再做 A/B/C/D 实验**  
   不要在金标未完成前急着跑实验。

## 12. 一句话结论

按 Chen 论文思路看，你目前最有价值的数据不是 1037 条 QA 的总量，而是能够把**地方标准依据、审核技能、真实样本链和人工复核任务**串起来的数据流；当前数据已经足够支撑中期汇报和方法试点，但正式实验还需要从 95 条样本链 QA 中筛选并精校 40-60 条金标题。
