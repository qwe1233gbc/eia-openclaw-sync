# 数据口径说明

## 1. 统计对象与版本优先级

论文设计按以下优先级使用材料：

1. 仓库内原始或结构化数据文件；
2. 仓库内由原始文件生成的统计报告，但关键数字必须复算；
3. 用户明确提供的外部附件；
4. 仓库外但为强制事实核对所必需的主工作簿，仅标为 `OUT-OF-REPO`；
5. 计划、PPT、会议结论和 Skill 快照不得替代数据文件。

## 3. 人工复核与金标口径

| 指标 | 数值 | 来源与统计方法 | 解释 |
|---|---:|---|---|
| `人工判断`非空 | 60 | 外部主表 `seed_qa`；本轮对 942 条 PL 记录做非空统计 | 仅说明字段已填，不自动等于专家金标 |
| `人工判断`为空 | 882 | 同上；`942 - 60` 亦可复核 | 尚无记录的人工判断 |
| `是否需要人工复核=是` | 922 | 同上；本轮值频数统计 | 仍明确要求人工复核 |
| `是否需要人工复核=否` | 20 | 同上；本轮值频数统计 | 也不自动等于通过专家金标 |
| `manual_check=True` | 942 | 同上；本轮值频数统计 | 表明整个主体池按候选题治理，而非完整金标 |

统一结论：当前 942 条只能称为**主体候选 QA 池**或**待裁决任务池**，不能称为“完整人工金标 Benchmark”。即便某字段非空，也必须进一步核对评审者身份、评审规则、证据充分性和是否完成争议裁决。

## 5. Skill 数量口径

仓库当前可核验的是：Git `HEAD` 中有 2 份 OpenClaw Skill 规格文档，另有 1 份 v0.6a 派生 Skill 卡。来源：`git ls-tree -r HEAD --name-only` 与 `rg --files`。三份文件属于同一综合审核路线的不同版本/产物，不能写成“3 个独立审核 Skill”。

外部 `write-evidence-grounded-environmental-sci.zip` 的 `references/eia-llm-study.md` 记录“15 个单项审核 Skill + 1 个综合 Skill”的 2026-07-19 快照，但仓库中没有对应的逐项清单、路径、版本和哈希。因此：

- 论文当前不得把“15 + 1”写为仓库已核实成果；
- 在补齐 `skill_manifest` 前，实验因素 S 统一定义为“一个冻结的结构化审核流程干预”，而不是按 Skill 文件数量计量；
- 若后续确实采用 15 个单项 Skill 与 1 个总控 Skill，必须列出每个 Skill 的名称、输入、输出、版本、依赖知识、是否嵌入标准条款和哈希，并重新统计。

## 6. 历史 QA 与主论文 QA 的隔离

`05_QA测试集/qa_batch_full.json` 有 419 条记录、181 个非空 `project_id`；来源：本轮 JSON 统计。`outputs/seed_qa_simple/` 和 `outputs/workflow_seed_qa_20260616_first_principles/` 各记录 180 道候选题；来源：对应报告。它们都是历史或平行资产，不与 942 条 PL 主体池相加，不用于证明 151 个项目。

## 7. 推荐冻结记录

正式实验前新增但不覆盖原文件的冻结记录，至少包括：

- 942 条主体池的仓库内副本、原路径、SHA-256、工作表名和字段字典；当前外部主表哈希为 `75dd13abb12d654582960ae89a546b396e7aba7955850bb65a211e6d54d34ab8`，来源：本轮哈希计算。
- 38 条标准卡的文件哈希与纳入/排除规则；38 条来源见第 4 节。
- Skill 清单、版本与哈希；当前为 `MISSING`。
- 项目级开发集/测试集分割表；当前为 `PLANNED`。
- 专家裁决表、盲法编码和一致性统计；当前为 `PLANNED`。

## 8. 本轮复算逻辑

本轮使用 bundled Python 的 `openpyxl` 以 `read_only=True, data_only=True` 打开主工作簿；对 `question_id` 做非空、前缀和唯一值统计，对 `canonical_project_id` 做集合去重，对人工字段做去空白后的频数统计，并对四个样本链工作表的 SC ID 与主表 SC ID 做集合相等检验。JSON/JSONL 采用逐条解析、唯一 ID 和字段非空统计。所有操作均为只读，未保存工作簿。
