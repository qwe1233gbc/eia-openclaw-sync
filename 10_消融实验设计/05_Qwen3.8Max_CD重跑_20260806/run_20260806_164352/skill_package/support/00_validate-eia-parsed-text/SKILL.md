# 环评解析文本保真核查

## 核心判定

把“差距不大”定义为审核等价，而不是逐字相同：审核人员仅阅读解析文本时，应能找到与原 Word 相同的决定性证据，并得到相同审核判断。

允许删除字体、颜色、空白、页眉页脚、重复表头、装饰图片和已有等价文字说明的图形；不得丢失或改写章节、表格行列关系、数值与单位、公式参数、工艺流程、污染源强、治理设施、危险废物、总量指标及其他可能改变审核结论的内容。

## 获取输入

完整保真核查必须同时取得：

1. 原始 `.docx`；
2. 对应的 `.json`、`.jsonl`、`.html`、`.md` 或 `.txt` 解析结果。

若只提供解析文本，输出 `仅结构自检`，检查乱码、截断、分块异常和章节结构，但不得给出“可作为人工审核输入”的最终结论。

## 执行流程

### 1. 运行确定性预检

在本技能目录运行：

```bash
python scripts/compare_docx_parsed.py --docx ORIGINAL.docx --parsed PARSED.json
```

需要保存结果时增加 `--output result.json`。该脚本检查正文覆盖、主章节、数字与单位、表格覆盖、分块 ID、HTML 标签平衡和序列化残片；脚本结论是预检，不替代下面的审核关键证据抽查。

### 2. 检查主结构

- 确认原 Word 中出现的环评主章节在解析文本中全部存在且顺序一致。
- 确认章节之间没有无提示跳跃、整段截断、重复拼接或跨章节串行。
- 对 JSON 分块检查 ID、顺序、重复和缺口。ID 缺号本身只算风险信号；若同时出现章节缺失或文本截断，则判为阻断问题。
- 检查是否混入 Python/JavaScript 对象字符串、异常栈、空对象、乱码、未闭合表格或解析器内部字段。

### 3. 抽查审核关键证据

读取 [references/acceptance-criteria.md](references/acceptance-criteria.md)，按其中的关键证据清单抽取 8–12 个检查点。至少覆盖：

- 建设项目基本信息；
- 产品、原辅材料、设备和工艺流程；
- 产污环节、源强参数、数值和单位；
- 收集与治理设施参数；
- 固体废物、危险废物和总量控制；
- 环境保护措施监督检查清单。

每个检查点只记录短定位和关键值，不复制长段原文。比较内容是否存在、语义是否一致、数值单位是否成对保留、表格的字段归属是否正确。

### 4. 检查图片、公式和复杂表格

- Word 含工艺流程图、总平面图、计算公式、文本框、嵌入对象或图片表格时，确认解析文本存在等价文字或结构化替代。
- 图片只起装饰作用，或其信息已由正文完整重复时，允许省略。
- 图片承载独有的工艺步骤、管线关系、敏感点位置或设备参数而解析结果没有文字替代时，判为阻断问题。
- 公式必须保留变量、数值、单位和运算关系；只保留计算结果不算完整。
- 表格转成线性文本时，必须仍能判断“字段—数值—单位—对象”的归属关系。

只有必须确认图片内文字或精确页码时，才使用文档渲染做针对性抽查，不默认逐页渲染整份报告。

### 5. 判定可用性

不要仅凭总分放行。按 [references/acceptance-criteria.md](references/acceptance-criteria.md) 的门槛和阻断项判定：

- `可用`：无阻断项，关键证据抽查通过，解析文本可直接作为人工审核输入；
- `修复后可用`：主体信息保留，但存在可定位、不会立即改变审核结论的结构或追溯问题；
- `不可用`：存在整章/关键表格缺失、数值单位错配、公式或图片独有证据丢失、明显截断、序列化污染等问题；
- `仅结构自检`：缺少原 Word，无法判断保真度。

轻量化比例只作为效率指标。即使压缩率很高，只要损失决定性证据，也必须判为 `不可用`。

### 6. 输出精简验收单

始终按 [references/output-template.md](references/output-template.md) 输出：

- 先给最终判定和一句话理由；
- 指标只列 6 项以内；
- 关键问题最多 5 条，每条原文摘录不超过 80 字；
- 修复建议最多 3 条，并指出应重新解析的章节或对象；
- 不输出长篇 Word 与解析文本对照全文。

## 批量验收

- 一一匹配原 Word 与解析文件，先验证文件名、项目名或项目 ID，避免错配。
- 逐项目运行脚本，并为失败项保留阻断代码和短证据。
- 汇总 `可用 / 修复后可用 / 不可用 / 仅结构自检` 数量，以及最常见的 5 类解析问题。
- 同一解析脚本升级后，用固定代表性报告重复验收，比较阻断项是否消失，避免只比较文件大小或 token 数。

## 完成前自检

- 是否同时比较了原 Word 与解析结果，而非只看解析文本是否流畅？
- 是否覆盖第四章污染源强和治理措施等高风险内容？
- 是否检查了表格字段归属、数字、单位和公式，而非只比较关键词？
- 是否抽查了图片或嵌入对象中的独有证据？
- 是否把压缩收益与内容保真分开评价？
- 是否用阻断项控制最终判定，而非用平均分掩盖关键缺失？
