# 精简验收单模板

## 单项目输出

```markdown
### 解析文本验收｜[项目名]

判定：可用 / 修复后可用 / 不可用 / 仅结构自检
理由：[一句话指出决定性依据]

核心指标
- 主章节：[已保留数]/[原Word存在数]，顺序：正常/异常
- 主体正文覆盖：[百分比]
- 数值及单位覆盖：[百分比]
- 表格：[原Word数量] → [解析结果数量]；关键表格异常：[数量]
- 分块：连续/缺号/重复/乱序
- 轻量化：[Word正文字符] → [解析纯文本字符]；文件大小仅作参考

关键问题（最多5条）
1. [严重度]｜[Word章节/表格或对象]｜[不超过80字的缺失或错配说明]

人工抽查
- [检查点]｜Word：[短值]｜解析：[短值]｜一致/不一致

修复建议（最多3条）
1. [重新解析的章节、表格、图片或分块及具体动作]
```

若判为 `可用`，关键问题写“未发现阻断问题”，但仍列出人工抽查覆盖范围。

## 批量汇总

```markdown
批次共__份：可用__、修复后可用__、不可用__、仅结构自检__。
常见问题：整章/漏块__、表格错位__、数值单位丢失__、图片证据缺失__、序列化污染__。
建议优先修复：[影响项目最多或涉及关键证据的解析问题]。
```

不要在汇总中粘贴长篇原文。每个失败项目保留阻断代码和一条短证据即可。
